## 1. Intended result

For every reply, show what its producing attempts consumed: ordinary input, cache reads, any separately reported cache writes, output and reported reasoning, with their applicable prices and accounting limits. Show cumulative totals across the conversation, including research, retries and responses that were rejected. An estimate must never masquerade as a provider charge, and missing data must never become zero.

Let the selected models request bounded research through a shared search/fetch service. Save the documents, links and exact passages in a conversation library that all authorized seats can search and read. Reuse saved versions and send relevant passages rather than repeatedly retrieving and injecting entire documents. Preserve opening independence, current claim revisions, evidence boundaries and the existing funding controls.

**Implementation strategy:** extend the current Council, using established libraries and focused mechanisms inspected in open agents. Do not replace it with thirteen other agent runtimes. The [repository survey](../docs/research/1.05/REPOSITORY_SURVEY.md) records 13 commit-pinned repositories, their root licences, 71 downloaded reference files and the selected source-level evidence. The [provider report](../docs/research/1.05/PROVIDER_COST_AND_SEARCH.md) separates public pricing/capabilities from unverified account entitlements.

## 6. Token and monetary accounting design

### 6.1 Records and invariants

Each `UsageRecord` links `call_id`, `logical_turn_id`, `chat_id`, cycle/phase, actual provider/model, original seat/replacement, request hash, raw artifact and adapter version. Store nullable measured categories with field-level states:

```text
input_total_reported
input_uncached
cache_read_input
cache_write_input { ordinary, long_retention }  # only when actually reported
output_total_reported
output_visible
output_reasoning
billable_output
provider_total_reported
normalization_status + inclusion_rules + raw_field_map
```

Canonical billable categories are disjoint. Display-only breakdowns declare their subset relationships. For one API, reasoning may be included in output; another may report visible/thinking separately. Do not sum provider totals with their components. Cached input is commonly part of prompt input; subtract it only when that adapter's documented convention requires it. Unknown cache writes are not `input_total - cache_read`.

`PriceCard` is immutable and identifies endpoint/model, account tier, modality, service class, context bracket, currency, input/read/write/output rates, storage units, tool charges, source URL, checked time, validity and precision. Distinguish `unsupported`, `not_reported`, `not_applicable`, known zero and invalid values. Different context brackets can price cached/uncached/output differently; select by the provider's defined context measure.

`CostAssessment` retains the exact price-card ID, charged components, known subtotal, missing components, tariff assumptions and one of `complete_estimate`, `partial_estimate`, `unknown`, `provider_reported` or `invalid`. Provider-reported amounts and calculated estimates occupy different fields. Historical repricing creates a new comparison record and never changes the original card or amount.

For nonoverlapping known components:

```text
token estimate = Σ(category tokens × category USD-per-million) / 1,000,000
storage estimate = Σ(cached tokens × elapsed hours × USD-per-million-token-hours) / 1,000,000
tool estimate = Σ(billable tool units × applicable unit price)
```

Use Decimal or integer fine-grained currency units for calculations. Current microdollar reservations remain conservative at admission; sum precise line items before display rounding. Validate NaN, infinity, negative/fractional token counts, impossible subsets, currency mismatch and unsupported modalities. Never silently coerce invalid/missing data into zero.

The proposed [12 accounting fixtures](../docs/research/1.05/COST_TEST_VECTORS.json) include cached-input overlap, missing telemetry, reasoning subsets, explicit synthetic writes, partial totals and shared overhead. Four numeric examples were checked with Decimal during planning; this is not a test run of an implemented calculator.

### 6.2 What a reply and chat total mean

- A **physical attempt** is the accounting unit, even when its response fails schema checks, is truncated, is cancelled after sending or is a research/tool request rather than a user-visible answer.
- A **reply total** groups its producing attempts by stable logical-turn ID. Retry/replacement costs remain visible; admission failure does not erase usage.
- **Shared research overhead** is a separate conversation bucket. Any per-reply allocation is labelled analytical attribution and excluded from financial summation to prevent double counting.
- **Conversation total** sums unique physical attempts plus unique search/fetch/cache billing events. State known token/cost subtotals and coverage, such as “usage reported for 9 of 11 attempts.” An incomplete total is not an exact total.
- A historical “cumulative after this reply” value specifies its ledger sequence/as-of time. Late provider results reconcile at a new sequence; they do not disappear because the final answer already exists.
- Budget authorization is based on the funding gate and worst-case uncached bound, not an expected cache discount. A list-price equivalent does not debit a free account or override its $0 authority.

## 7. Shared conversation library

### 7.1 Scope and storage

“Shared repository” means a local **conversation source library**, not mandatory Git hosting or shared access to the whole workstation. Every selected model can use the same library tools under a scoped capability. Cross-chat sharing requires an explicit user action; a global blob store may deduplicate bytes but must not leak another chat's documents through search, IDs or cached receipts.

Suggested records:

| Record | Required content |
| --- | --- |
| `Source` | Chat/project scope, canonical URL or user-selected import identity, origin, title, access/freshness policy. |
| `SourceVersion` | Immutable raw/text hashes, fetch/import time, reported publication time, final URL/redirect chain, MIME, HTTP validators, parser version, extraction/coverage limits. |
| `SourceChunk` | Version ID, stable chunk ID, heading/page/line/character spans, exact extracted text, chunking version. |
| `LibrarySnapshot` | Ordered source-version IDs, current research stage, provenance and publication dependency links. |
| `ResearchNote` | Append-only model/human note, author and basis references; never an authoritative replacement for source text. |
| `ReadReceipt` | Which seat/turn received which version/chunks, range, truncated flag and context-pack hash. |
| `CitationBinding` | Statement/claim revision, source-version/span, quote-match result and separately attributed support assessment. |

Use existing artifact storage for raw bytes/manifests and SQLite for authority/index metadata. Import only explicitly chosen files. Ignore credential/config secret files; detect configured secrets in material before external submission. Start with text/Markdown/HTML, then bounded PDF/DOCX text extraction using maintained libraries after licence/fixture checks. No OCR/model/GPU dependency. Preserve page/paragraph/heading locators and flag OCR-only or incompletely extracted content.

Set a configurable library storage bound and stop new ingestion when it is reached. Expiring a fetch cache must not delete an immutable source version needed by a publication. Export has an explicit per-source content-inclusion policy: a reference-only/redacted pack must report its offline-replay limits rather than claim to reproduce missing source bytes.

Local lookup uses SQLite FTS5/BM25, exact title/URL/ID filters and bounded line/chunk reads. If FTS5 is unavailable, report the capability and provide a small bounded lexical fallback; do not silently install a cloud vector service. Embeddings/rerankers remain optional later work justified by measured retrieval misses.

An in-memory probe confirmed FTS5 in the current local SQLite 3.40.1 runtime. This is environment readiness, not an application schema migration; the [research validation](../docs/research/1.05/RESEARCH_VALIDATION.json) records that distinction.

### 7.2 Retrieval tools

```text
library.search(query, top_k, snapshot_id, filters)
library.read(version_id, chunk_ids OR bounded_range, snapshot_id)
web.search(query, domains, freshness, limit)
web.fetch(url OR search_result_id)
research.note(text, source_refs)  # optional append-only notes; never file mutation
```

Every result contains immutable references, status, provenance, truncation/freshness and a byte/token budget. An ID alone does not let a model “remember” unseen text: the needed passage must be in its current context or supplied by a counted continuation. Tools cannot read arbitrary host paths, fetch localhost/private networks or write project source code.

## 8. Web search and bounded model tool use

### 8.1 Search-provider decision

Use a provider-neutral broker. The first optional adapter is **Tavily free Researcher / Basic Search**, with no paid-overage mode and a local reserved-credit ceiling. Its current public allowance is recorded in the [provider report](../docs/research/1.05/PROVIDER_COST_AND_SEARCH.md#web-search-practical-initial-choice). `TAVILY_API_KEY` is the only proposed new credential. No key is created, no account is configured and no paid request is authorized here.

Only broker adapters may use operator-configured service endpoints. A future local SearXNG endpoint has its own explicit trusted transport configuration; it does not grant model-supplied `web.fetch` URLs permission to access private networks. Search queries are bounded public-information requests, not automatic uploads of whole private documents or workstation content.

When unavailable, allow supplied sources, direct public URLs and local library reads, and state that broad web search is unavailable. An operator-controlled local SearXNG adapter is a later option; arbitrary public instances and credential-free scraping are not a reliable default. Existing Z.ai/Gemini/Groq keys must not automatically activate native paid search. Search credentials and exact model-generation credentials are independent.

### 8.2 Tool continuation protocol

Current adapters deliberately forbid tools. Introduce a typed `ResearchAction` boundary and exact-model capability tests rather than attaching an unbounded autonomous agent:

1. Compile an allowed tool catalogue, source snapshot and remaining resource envelope for the current seat/stage.
2. Admit a native function/tool request, or a separately validated structured-action response for models whose native tool contract is unsupported. Never parse arbitrary prose into commands.
3. Validate arguments, scope, deadline and reserved credits; execute only allowlisted read/search/fetch/note operations.
4. Persist request/result receipts and update the library snapshot at the permitted barrier.
5. Continue the same logical turn with provider-native call IDs/response parts and any required opaque signatures intact. The continuation is another physical model call and is counted.
6. Freeze the evidence/context pack and complete the existing stage's ordinary answer/strict response schema. A tool request is not a finished opening, repaired claim or final answer.

Research mode and final structured-stage emission are separate steps when a provider cannot combine native tools with the required response format. Do not discard function-call metadata by treating a `tool_calls` finish reason as a failed blank response. Preserve opaque provider continuation fields without decoding or displaying private reasoning. No hidden format-repair/summarizer request or alternate generation model is added.

### 8.3 Default resource envelope

The initial configuration is a tunable, explicit software policy, not a promise that upstream free quotas suffice:

| Resource | Proposed default |
| --- | --- |
| Four-seat base review | 12 completed logical contributions (`2N + 4`), as today. |
| Additional research request/continuation calls | At most **5** physical model calls total per full request; includes any pre-opening planner and any optional model summary. |
| Shared recovery pool | Existing **3** additional failed/retry/substitution attempts. Tool usage does not create another retry pool. |
| Maximum four-seat model attempt envelope | **12 + 5 + 3 = 20**, subject to daily/provider availability and token limits. Reserve before dispatch. |
| Web search requests | At most **3** Basic Search queries per full request; each separately reserved, cached where valid and limited to 5 returned results. |
| URL retrieval | At most **6** unique network fetch attempts; a redirect chain belongs to that bounded fetch, with its own hard redirect cap. |
| Tool continuation batches | At most **2** for one logical contribution and always inside the global 5-call research pool. |
| Local library reads | No external charge, but bounded by per-result output limits, context tokens, invocation count and wall-clock deadline. |
| Initial local-read cap | 12 local read/search invocations, top-k ≤ 5, each read ≤ 16 KiB extracted text and aggregate retrieved text ≤ 48 KiB per logical contribution; actual model input cap can require smaller chunks. |
| Initial fetch bounds | 20s wall deadline, ≤ 3 redirects, ≤ 2 MiB decoded text/PDF extraction input per response, and ≤ 12 MiB total raw fetch bytes per request; compressed-body and parser expansion caps are separate. These conservative pilot limits must be tested, not inherited from a 1M-token model card. |
| Concurrency | Start with 2 public fetches globally and 1 model call per provider; model opening parallelism is separately gated. |

The optional focused exchange may use capacity only when the **actual remaining base work + final + recovery reserve + admitted research** still fit. It is not added on top of a fully used 20-attempt research envelope. Tool continuation capacity is reserved so a seat is not invited to call a tool whose answer it cannot afford to process. If native tools cannot be safely enabled within the remaining pool, expose only server-prepacked passages and a deferred research-gap record, or hold the step explicitly.

For accounting classification, one final-producing physical call per logical contribution belongs to the base 12. Each other successful intermediate/planning/summary call belongs to the research pool; failed/rejected recovery attempts belong to the existing recovery pool. A final-producing continuation is not charged to both base and research. Every physical attempt appears exactly once in the global attempt count regardless of this explanatory grouping.

Read-only explanation follow-ups keep their existing one-call purpose and do not silently browse. Targeted challenges get a separately previewed smaller research allowance based on the affected claims. An explicit larger/new request may open a new bounded window in the same chat under current rules; automatic recovery never opens a fresh window or erases cumulative usage.

### 8.4 Independent research exposure

A neutral pre-opening research plan may use one of the five extra calls to propose search questions and source types, without drafting model answers. Fetch those sources into snapshot **S0** before independent openings. Every opening receives the same shared source inventory and its own declared passage selection; no current peer answer is included. This is independent answering from common evidence, not independent discovery of evidence.

During openings, models may read S0 or record additional research gaps. New web discoveries requested then are queued for the next barrier rather than silently changing the evidence available halfway through the opening cohort. After the opening barrier, admit a bounded research batch into **S1** and declare which later stages/seats receive it. Sources can change conclusions only through visible revision/recheck; no rewriting earlier opening text. Every context pack records its exposure snapshot and exact passages actually sent.

## 9. Context and cache efficiency

### 9.1 Context packs

Compile prompts from named, versioned segments rather than a single changing JSON blob:

```text
Stable per provider/model/role/schema:
  system instructions → fixed tool definitions → phase schema/policy
Stable per approved evidence snapshot, where privacy/exposure permits:
  source inventory → deliberately selected passages → frozen task constraints
Dynamic suffix:
  current request → current claim revisions/findings → current stage action
```

Keep live accounting, timestamps, random request IDs and retry counters out of a reusable prefix. Hashes and metadata still belong in the stored execution record; omitting transport metadata from a prompt does not mean omitting it from the audit trail. Do not move peer answers into an opening prefix to gain cache hits. A role/model/schema change creates a different namespace. Native provider caches cannot be transferred between Z.ai, Gemini, NVIDIA and Groq, and local document storage is not a provider KV cache.

A `ContextPack` records its source snapshot, exact chunk IDs/ranges, mandatory current claims/findings, omitted material and reason, estimated token method/bounds, request bytes, ordered segment hashes, compilation version and eventual provider usage. A component's estimated tokens must not be displayed as measured provider tokens. Cached-read ratios are calculated only from compatible reported categories; unknown denominators produce unknown ratios.

Selection order: current user constraints and intervention → required unresolved/dependent assertions/findings → directly supporting or challenging passages → relevant prior decisions → optional background. Ranking may combine FTS score, claim relevance, source freshness, diversity and source priority, with deterministic tie-breaking. Do not claim an exact semantic ranking from lexical scores alone. If mandatory material cannot fit, hold/narrow the stage explicitly instead of dropping obligations.

### 9.2 Cache policy

Use stable prefixes for supported implicit caching first, with no additional warmup requests. Record actual returned cache counts; prefix equality is an opportunity, not a measured cache hit. Cache handles, minimum token thresholds, TTL, account tier, schema/tool restrictions and storage pricing are exact-provider capabilities, not universal flags.

Explicit cache creation is off by default under current funding. A future eligible configuration must establish all lifecycle charges, expected reuse and deletion/expiry. Admit it only if authorized worst-case cost fits and its expected avoided ordinary-input cost exceeds creation/storage/refresh and extra-call costs. Free generation tariffs can make monetary savings zero even when latency benefits are possible; do not create paid caches to optimize free input.

No keepalive traffic, speculative cache warmers, automatic paid cache upgrades, padded prompts just to cross a cache threshold or model changes to chase a cheaper token price. An expired handle falls back to a recompiled ordinary prompt only if the original bounded allowance still covers it; it does not reset the request allowance.

### 9.3 Compaction policy

Prefer deterministic removal of repeated transport fields, source-body offload, exact current-record selection and bounded re-reading. Compact only derived context, not saved messages or source versions. Keep the current user request, hard constraints, unresolved objections, original/current claim wording where required, dependency revisions, dissent, source bindings, ordinary-risk distinctions and publication blockers outside any lossy summary.

An optional LLM summary is a counted model request with an explicit `summary_of` manifest and provenance `model_reported`, never a new user instruction or empirical evidence. It shares the research call pool, cannot recurse, must show actual size reduction, and is rejected when protected facts are missing or required context no longer fits. Original passages remain retrievable. One-off summary prompts do not automatically merit cache writes. A stored summary cannot close a finding or upgrade evidence.

## 10. Concurrency, UI and observability

### 10.1 Controlled concurrency

Start with deduplicated read-only HTTP work. Maintain global and provider-specific semaphores, exact batch configuration leases, reserved resource slices, deadlines and cancellation tokens. Do not keep SQLite write transactions open while waiting for HTTP. Native searches that consume credits remain budgeted even when logically read-only.

Initial limits: two network fetches globally; one model call per provider. Until P2 is enabled, model contributions remain sequential as today. The first parallel-opening pilot additionally caps model calls at two globally, with no parallel dependent author-response sequence.

Model opening parallelism is a separate P2 optimization. Permit it only after the shared S0 packet is frozen and independent per-seat contexts are built. Use existing durable jobs with claimed step IDs, a reveal barrier and atomic attempt/token reservations; no shared mutable prompt or intermediate answer leaks between seats. The worker count is bounded inside one coordinated server; launching another executor against the same data directory is not the concurrency design.

Unknown provider quotas keep conservative limits. Cache reuse does not authorize flooding a provider: some token deductions occur only after requests complete. Later author-response deliberation stays ordered where it depends on preceding public replies. A late result is attributed and stored even if no longer eligible for publication. No remote search/model call is assumed idempotent because a local request ID was reused.

### 10.2 Simple and Explain

| Surface | Simple | Explain |
| --- | --- | --- |
| Reply usage | Compact **Usage** line; show known tokens and clearly labelled price estimate or “usage unavailable.” Expand on request. | Per-attempt/category table: uncached input, cache read/write, output, reasoning relationship, unit rate, actual model, status and source fields. |
| Conversation total | One quiet **Conversation usage** entry; partial/unknown totals and provider-reported versus estimate labels remain visible. | Breakdown by response/cycle/provider/model plus shared research, retries, unknown outcomes, coverage and rate versions. |
| Library | **Sources** button, saved documents/links and readable passages/citations. | Version/hash/parser metadata, read receipts, freshness, extraction limits and citation/support provenance. |

Do not replace the calm composer with a token dashboard. Price unit labels must state currency and denominator. Tool invocation must be visible activity, not hidden chain of thought. Diagnostics and page refreshes never trigger research, recalculate with a new paid rate, refresh source URLs or create caches. **Explain view** remains a free presentation change; **Explain this answer** remains an explicit model follow-up.

### 10.3 Efficiency evaluation

Record source bytes retrieved, unique URLs, HTTP/search invocations, reused receipts, local-index latency, selected context bytes/estimated tokens, reported token categories, usage coverage, model/tool call count, wall time, provider latency, retry/exhaustion counts and declared cost views. Report p50/p95 only for enough stated comparable runs; do not invent time-to-first-token from the current nonstreaming adapter's total latency.

Use controlled comparisons:

1. Repeated same-document request versus the same evidence injected again; report avoided network work and actual model input separately.
2. Full-document context versus source-index/range context with identical relevant evidence, questions and exact models.
3. Cold/eligible repeated-prefix runs per provider, recording actual cache telemetry; no guaranteed cache-hit percentage.
4. Sequential versus bounded I/O concurrency under the same call/token/credit envelope, including failures and provider waits.
5. One optimization at a time before a combined configuration, preserving original reviewed output quality/coverage checks.

A four-seat duplicate-fetch fixture should prove one remote fetch and four read receipts; that is a deterministic duplicate case, not a general 75% performance claim. Latency and token reductions are hypotheses until measured. Search may improve grounding but can also introduce noise or malicious text. Evaluate exact-source coverage, citation validity, missing qualifiers, unreviewed assumptions and answer usefulness alongside efficiency. Independent semantic labels remain independent work, not a model-graded victory.

## 12. Readiness and deliberate exclusions

Required from implementation: no new GPU or model provider. Existing four keys suffice for generation, subject to their actual access and limits. Optional broad web search requires a free-only Tavily key or an explicitly operated alternative. Before that, the library/calculator/local lookup still work and the interface must state the search limitation.

The following are intentionally outside this increment: replacing Council with a general coding agent, importing every upstream plugin/tool, unrestricted shell/browser automation, automatic subagent swarms, paid embeddings/rerankers, cache keepalive jobs, hidden LLM repair calls, automatic native paid search, global cross-chat memory, vector-database infrastructure, changing models to chase price, and claiming independent reasoning superiority from token savings.

The completed deliverable should be a Council that can show what work cost, reuse the evidence it already has, request additional evidence under explicit bounds and make its remaining uncertainty visible. The software implementation and checklist evidence are complete. Conditional paid-cache, LLM-summary and parallel-opening activation gates remain closed; completion means those policies are enforced, not that these optional capabilities were enabled.
