# Live activation is a separate operator action

The director explicitly asked on October 18 to keep inference locked while building. The application honors that: the local development data has no live verification record, the policy file defaults to disabled, and no startup, test, demo seed or reproduction command sends inference.

On October 21 the user confirmed a $25 account balance and a separate $1 trial with 26 days remaining, and instructed an aggregate $24 limit. Council records that balance as user-reported evidence and enforces a **$24 maximum across all Token Factory chats and missions in this application data directory**, including settled work, schedule holds, in-flight reservations and ambiguous charges. The trial does not enlarge the limit. Existing verification records authorizing $25 are clamped to $24; new mission/council/verification requests above $24 are refused. No conversation, resume or verification renewal resets the global ledger.

This balance confirmation is separate from bank-card automatic collection and model-price/token-bound verification. Do not record those prerequisites as true solely from the balance. The application limit cannot control spending by other clients using the same account or certify a provider invoice. No inference was authorized or dispatched by the limit change.

Use the Provider & Spending Controls dialog to inspect the exact model catalog and record actual evidence. `catalog_model_ids` must contain only verified enabled IDs. Prices use USD per million input/output tokens, not USD per token. Record the source, timestamp and scope. Public price references in `benchmark/model_manifest.json` are not automatic authorization.

The request uses `max_completion_tokens`, which the official API schema describes as including visible and reasoning output. Verify support and billing for the exact model/account before asserting the output envelope. `additional_billed_output_tokens` and `billed_input_multiplier` are conservative budget-envelope additions; they do not change provider parameters. The adapter counts serialized UTF-8 bytes plus 4096 framing bytes, multiplied by the verified multiplier, as its input reservation envelope. This is deliberately conservative, not a measured tokenizer count. Every billed category must fit the confirmed envelope and prices; otherwise leave dispatch locked.

Start with a $0.05–$0.25 mission allowance and a small global operational cap. A single `inference.run_trial` with 32–64 completion tokens can establish a runtime NVIDIA response after all prerequisites. Preserve the returned artifact, actual model, usage and settled/unknown charge before increasing scope. Do not treat an HTTP error or missing usage as a free call. There are no automatic HTTP, JSON repair or timeout retries; an explicit continuation/new attempt reserves again while old unknown charges remain counted.

The controlled pilot requires a frozen **live** mission and explicit approval for the fast-first treatment. The executor reserves the complete schedule, including one potential escalation for every routed trial, before dispatch. If it does not fit, nothing is sent. Confirmation uses the same exploratory strategy and a separate authored task split. Complete human quality review must cite the measured benchmark evidence. A confirmed decision requires all gates; fixture/imported comparisons cannot impersonate live confirmation.

To disable live work, use Lock Live Dispatch. This stops future provider verification; cancel queued experiments as appropriate. Already-sent requests may complete and incur charges. Unknown reservations are never automatically released. To reconcile an ambiguous charge, inspect provider usage and preserve evidence; the initial candidate intentionally has no generic 'forgive charge' button. Keeping a conservative unknown reservation is safe and may reduce available experiments.

No AI Cloud project, GPU quota, LangSmith, Tavily, Toloka or Tendem credential is required. Optional genuinely free hardware work remains separate.
