# Council continuity and readable replies

October 19, 2026. Application version 1.2.1. This patch changes execution and presentation; it does not claim independent scientific validation or complete the pending 1.02 quality pilot.

## Compatibility check

The apparent removal of 1.01 code was a split into versioned files. Compared directly with `data/releases/ZeroWall-1.01-local-test-build.zip`, `review_policy_v1.py` is identical. Its SHA-256 remains `9bc86f0fb6b0194d8a924a2775eb8f52faa8809128af74506553574162310a4f`. The original 1,232-line engine remains in `council_review_v1.py`. Its only differences from the archive are the pinned v1 policy import and this patch's exemption of direct-provider chats from the old six-cycle ceiling. Frozen v1 publications still reproduce with the original hashes. The router chooses the saved protocol; it does not reinterpret old review decisions as v2.

## Behavior

- A direct-provider follow-up opens a new allowance of at most twenty attempts in the same chat. Unused allowance from an earlier request does not accumulate. All sent attempts, failures, unknown outcomes, messages and publications remain saved. Each grant has a durable audit record. A retry or resume alone does not grant another allowance.
- The daily application cap remains one hundred attempts per UTC day, across chats in the database. A real daily shortage asks the user to return to this chat after reset. Keys do not reset accounting. No paid fallback, automatic top-up, GPU use or Token Factory billing unlock was added.
- Discussion follow-ups start one new round and a new final answer. They do not backfill abandoned older rounds, replay successful openings, or hit the old six-round ceiling. Explicit messages can continue a stopped or unavailable direct conversation. Review follow-ups preserve old cycles and start a full bounded review cycle with their own immutable contract.
- Gemini leads Discussion synthesis when selected and available. New reviews already assign Gemini extraction and synthesis. Historical model authorship and explicit reviewed role assignments remain intact.
- Groq GPT OSS 120B switches to the explicitly allowlisted `openai/gpt-oss-20b` after two eligible sent failures. Saved consecutive failures count across a follow-up. Only one substitution is permitted for that seat; the replacement is named in subsequent replies and audited. Authentication, billing, cost locks and model identity failures do not authorize substitution. Both models are listed in Groq's [free-plan limits](https://console.groq.com/docs/rate-limits); the account catalog also listed the alternative during this patch's metadata-only check. Free access and provider availability remain distinct.
- Groq Discussion uses a declared excerpt window, initially bounded to 10,500 UTF-8 bytes and reduced to 7,000 after HTTP 413. Its output allowance starts at 3,072 tokens and grows to 4,096 on a truncation retry, within the same attempt ceiling. The original question and latest director note remain complete. Older peer text can be excerpted; all original messages remain saved. Required structured review material is not silently dropped to meet this window. Provider quotas and tokenizer differences can still prevent a request. A separate participation record identifies the actual model and phase that failed, independently of generated synthesis prose.
- Ordinary answers explicitly request readable Markdown. Internal review phases keep strict structured contracts. A display adapter turns structured replies and JSON code fences into labelled sections and lists; the exact original response remains expandable and exportable. A narrow local display repair handles old JSON containing unescaped TeX commands; complete flat string fields with broken quoting can display as labelled lines without dropping a field. Other unparseable content stays visible as written. Stored source and admission validation are unchanged.
- Saved and new formulas render using local KaTeX, supporting dollar math, standard slash delimiters, and narrowly recognized legacy bare delimiters. Code stays literal. Untrusted HTML, external images and trusted TeX commands stay disabled. Formula rendering does not establish the correctness of a scientific derivation.
- Dark mode is the council default, including its inspector, composer, tables and native form controls. The title uses normal letter spacing, explicit word spacing and up to two lines; the former global negative tracking no longer compresses it. The transcript uses fourteen-pixel text on mobile and desktop.

## Validation

Regression coverage includes continuation beyond forty cumulative calls and six rounds, daily-cap enforcement, idempotent grants, both review versions and prior publications, exactly two Groq failures before substitution, forbidden billing/auth substitutions, bounded context, structured presentation, mathematical rendering, unsafe content and mobile layout. See `docs/validation/council-continuation-backend.xml` and the browser suite. Actual-provider continuation is recorded separately from deterministic transport checks.

The [live continuation](../validation/council-continuation-live.json) preserved the physics conversation and its prior messages, moving from seventeen to twenty-five cumulative attempts. Gemini completed the requested five-approach synthesis. Z.ai recovered from two rate-limit responses. Groq's named alternative truncated twice under the initial 1,536-token output allowance; this final remains partial, and no further live rerun was started. The later output-envelope correction is covered by transport tests. The [actual-page check](../validation/council-readability-ui.json) rendered 142 formulas with no formula errors, four structured replies and fitting layouts at 622 and 390 pixels. The [validation register](../validation/council-continuation-status.json) preserves test counts, compatibility checks and remaining limitations.

The previous 1.02 release archive and its validation records remain unchanged historical artifacts.
